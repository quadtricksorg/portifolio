# QuadTricks website

The portfolio and marketing site for QuadTricks, a creative technology studio. It is a single-page site: Work, Services, Process, About and Contact are sections of the homepage, reached with `/#work`, `/#services`, `/#process`, `/#about` and `/#contact` (the old `/work`, `/services`, `/about`, `/process` and `/contact` addresses redirect there). Each project and each service also has its own detail page. Built with Next.js 16 (App Router, Cache Components), TypeScript, Tailwind CSS 4, Framer Motion, GSAP and Lenis.

- Design and decisions: [docs/BLUEPRINT.md](docs/BLUEPRINT.md)
- Content still needed from QuadTricks: [docs/CONTENT-TODO.md](docs/CONTENT-TODO.md)

## Run locally

Requires Node.js 20.9 or newer.

```bash
npm install
cp .env.example .env.local   # optional for local work
npm run dev                  # http://localhost:3000
```

Other scripts:

```bash
npm run build      # production build
npm run start      # serve the production build
npm run lint       # ESLint
npm run typecheck  # route types + TypeScript
```

The contact form sends email through Gmail SMTP using an app password (`SMTP_USER`, `SMTP_PASS` in `.env.local`). Without them, it logs enquiries to the terminal in development, and in production it shows a friendly error that points visitors to the studio email address.

## Editing content

All content lives in typed files under `src/content/`. Each file is validated at build time, so a mistake fails the build with a clear message instead of breaking the live site.

| File | What it holds |
| --- | --- |
| `site.ts` | Name, domain, contact details, locations, social links, support promise. Fields marked `TODO` need real values. |
| `services.ts` | The six services: promise, use cases, deliverables, process, technologies, FAQ, SEO text. |
| `projects.ts` | Portfolio projects. Empty until real, client-approved work is added. |
| `about.ts` | Story, the four disciplines and values. Founders are intentionally not named. |
| `process.ts` | The five process stages. |
| `home.ts` | Hero words, intro statement, marquee and the four advantages. |

### Adding or updating a project

The six current projects use concept mockup images generated by `scripts/generate-concept-visuals.mjs` and marked with `conceptVisuals: true`. When you have real screenshots, replace the files in `public/work/<slug>/` and set `conceptVisuals: false`.

1. Put images in `public/work/<project-slug>/` (JPG or PNG; Next.js optimises them automatically). Website covers work best at 1600x1000, app covers as portrait screenshots (about 900x1800).
2. Add an entry to the `raw` array in `src/content/projects.ts`. The example in the file comment shows every field.
3. Set `featured: true` to show it on the homepage (the first four featured projects appear). Set `liveUrl` to show a "Visit the website" or "Get the app" button.
4. Optional flagship blocks (`video`, `beforeAfter`, `timeline`, `outcome`, `quote`) appear only when you provide them. Use `outcome` and `quote` only for verified results and real, attributable client quotes.

Every project appears in the Work section of the homepage and gets its own case study page at `/work/<slug>`. Project categories are Web Applications (websites and web apps together), Mobile Apps, Branding, Animation and Cloud.

## Deploying

Recommended host: Vercel.

1. Push this folder to a Git repository and import it in Vercel.
2. Add the environment variables from `.env.example`.
3. Set the production domain, then update `url` in `src/content/site.ts` to match. It is used for canonical URLs, the sitemap and social cards.
4. Add `SMTP_USER` and `SMTP_PASS` (the Gmail app password) in the host's environment variables. Never commit them.

Any Node.js host that runs `next start` also works.

## Design system

Tokens are CSS variables in `src/app/globals.css`, mapped to Tailwind utilities (`bg-bg`, `text-fg-muted`, `text-accent-text`, `border-border`, and so on). Dark is the default theme; light is fully supported and the visitor's choice is remembered.

Brand utilities: `chamfer` (cut corner from the logo), `tri` (the orange triangle indicator), `label` (mono uppercase eyebrow), `container-x` and `section-y` (layout rhythm).

All motion respects `prefers-reduced-motion`. Smooth scrolling is disabled on touch devices and for reduced-motion users.

## SEO and performance

- Every page builds its metadata with `pageMetadata()` in `src/lib/seo.ts`: title, description, canonical URL, Open Graph and Twitter cards, all in one place. Detail pages also emit breadcrumb structured data.
- The homepage search snippet is `site.metaDescription` in `src/content/site.ts`; keep it under about 160 characters.
- Set the real domain in `site.url` before launch: canonical URLs, the sitemap, robots.txt and structured data all derive from it.
- Client components receive content as props from server components. Do not import `src/content/*` modules that validate with zod (services, projects) or `src/lib/schemas.ts` into a `"use client"` file, or zod ships to the browser; category labels live in the zod-free `src/lib/categories.ts`.
- Animations use framer-motion's slim `m.*` components inside `MotionProvider` (strict `LazyMotion`). Importing `motion` instead raises an error, by design.

## 3D background

The site-wide "solar system" background (chrome "4" emblem, red glow, orbit rings, sparkles) is a three.js port of the original sample site's scene: `src/components/brand/emblem-scene.ts`, mounted by `BrandScene.tsx`.

- It loads after the page has painted (browser idle time) and fades in; until then a CSS starfield and rings show.
- Devices without hardware WebGL keep the CSS fallback and never download three.js.
- Phones: lower resolution, simpler metal material, fewer sparkles, a sprite glow instead of bloom.
- All devices: quality steps down automatically if the frame rate drops; rendering stops while the tab is hidden; reduced motion turns off float, spin and twinkle.
- Light and dark themes are read from `data-theme` and update live.
- Frosted blur (`glass-blur`) is only on the header. Panels use `glass`, a translucent tint without blur, because blurring over an animated background every frame is costly.

The scroll path of the emblem is the `KEYS` table at the top of `emblem-scene.ts` (six keyframes across the whole page).
